# 🚨 ARCHITECTURE REMINDER: UUID PRIMARY KEYS

## 📋 PROJECT-SPECIFIC CONVENTION

### 🔑 PRIMARY KEY STRATEGY
- **ALL Models**: Use UUID v4 as primary keys
- **Key Type**: `protected $keyType = 'string'`
- **Incrementing**: `public $incrementing = false`
- **Column Type**: `string` (NOT `bigInteger`)

### 🗄️ DATABASE COLUMN TYPES
- **Foreign Keys**: MUST be `string` type to store UUIDs
- **Morph Columns**: MUST be `string` type for UUID references
- **Example**: `$table->string('causer_id')` NOT `$table->unsignedBigInteger('causer_id')`

### 📝 MIGRATION PATTERNS

**CORRECT (UUID Project):**
```php
// Foreign key columns
$table->string('user_id');
$table->string('causer_id')->nullable();

// Morph columns  
$table->string('subject_id')->nullable();
$table->string('subject_type')->nullable();
$table->string('causer_id')->nullable();
$table->string('causer_type')->nullable();

// Changing existing columns
$table->string('causer_id')->nullable()->change();
```

**WRONG (Auto-increment Project):**
```php
// These would break UUID relationships!
$table->unsignedBigInteger('user_id');
$table->unsignedBigInteger('causer_id')->nullable();
```

### 🏗️ MODEL CONFIGURATION
All models extend base classes with:
```php
protected $keyType = 'string';
public $incrementing = false;
```

### 🔍 VERIFICATION COMMANDS
```bash
# Check for UUID configuration
grep -r "protected \$keyType.*string" app/ Modules/
grep -r "public \$incrementing.*false" app/ Modules/

# Check migration patterns  
grep -r "unsignedBigInteger.*causer" database/
```

### 🚫 COMMON MISTAKES TO AVOID
1. Assuming auto-increment IDs (`bigInteger`)
2. Using `unsignedBigInteger` for foreign keys
3. Forgetting that morph columns need `string` type
4. Not making relationship columns nullable when appropriate

### ✅ BEST PRACTICES
1. Always use `string` for foreign key columns
2. Make polymorphic relationships nullable
3. Verify column types match the UUID strategy
4. Check existing models before creating migrations
